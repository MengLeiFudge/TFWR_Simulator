# 建材深钻

入口为 [block.py](../scripts/functional/block.py)，保留 `block(target=-1)`：无参持续生产，传入非负库存下限后达标返回。入口使用全科技、32×32普通农场、一台无人机和唯一爆破钻。运行前会清场；同次执行尚未使用Jump时，通过 `production.jump_once(Unlocks.Dynamite)` 跳到原生炸药层附近。

## 开采路径

主机在同一根孔中连续向下开挖。爆破钻每次消耗一份Dynamite，以 `Dynamite.Explode(..., collectDrops: true)` 收集实际清除的地块掉落。爆炸触及原生雷块或煤灰时补充传播能量，经过这些地层时会出现批量入库。持续向下保留已打开的深孔，避免反复换回收益较低的浅层。

塌方清掉的块不会自动变成收益。脚本只依据真实Block库存核算，不把爆炸范围、移动数或理论块数填写为产量。无法挖掘或动作失败时报告原因并返回。原版在炸药不足时仍可能让 `dig()` 成功，但不触发爆破钻爆炸；当前入口只检查动作返回值，因此直接运行也必须预备炸药，不能把缺料手挖当成持续爆破验证。

`resources.materials(Items.Block)`按 `block.DYNAMITE_RESERVE` 准备2000份Dynamite。该数量是一次补料储备，不限制整次持续生产的挖掘次数。原生扫雷层可能额外发放炸药；实际净消耗以库存为准。此入口只依赖同目录的 `production.py`，不消耗向日葵种子或临时土台。

## 采矿大师的窗口

成就目标是60游戏秒内获得1,000,000 Block，平均约16,666.67/游戏秒。原版 `Simulation.RecordCollectedItem` 把 `CurrentTime` 传给 `Achievements.CollectItem`，后者按60秒 `Duration` 维护滑动窗口；这是游戏内时钟，不是本地模拟程序的墙钟耗时。窗口从入口初始化前的真实库存开始，包含清场、调整地图、首次Jump和全部挖掘。每次结算后记录时间和Block库存，并淘汰超过60秒的起点。

`block_drill`输出挖掘次数、深度、当前游戏时间和窗口净增。当前入口每16次挖掘采样一次库存和时间，减少查询对爆破路径的干扰；窗口判定仍只使用实际入库的Block，不把爆炸范围当作产量。只有实际窗口净增达到1M，才报告“采矿大师数量条件已达到”。这表示脚本可观察的数量条件成立，不读取Steam成就状态。历史窗口按下标淘汰，分段压缩，避免每次从列表头删除而反复移动全部历史数据。

快速筛选可用10游戏秒的净增长乘6估算一分钟产量，但须明确初始材料、是否包含准备阶段和速率稳定性。原生炸药层会造成批量入库，短窗口外推不能单独判定不达标。C#已完成下方同源码seed=1的60游戏秒复核；历史三seed结果继续单列，不混作同版本复测。

`block.py`仍是持续功能入口。成就验证使用现有库存目标参数，只生产本次新增的1M后自然退出；单次验证最多5分钟，不把这个限制加到用户的持续生产调用中。

## 效率与验证

同一全科技普通场景、初始Block与Dynamite各1M、Power充足，包含初始化。下表为三个seed的已完成本地模拟，不是速率外推。

| seed | 实际游戏秒 | Block实际净增 | 采矿大师窗口秒 |
| --- | ---: | ---: | ---: |
| 0 | 47.41360596 | 1,000,035 | 47.40702156 |
| 1 | 52.35816114 | 1,044,395 | 52.35157674 |
| 2 | 56.50402860 | 1,003,687 | 56.49744420 |

同条件下，当前存档旧浅孔版在300.02872104游戏秒内净增150,289，约500.915 Block/游戏秒。以上新版本在各自已完成窗口约17,763～21,092 Block/游戏秒。它们描述这些随机轨迹和窗口，不承诺所有地层的稳态速率。

实机请求491使用动态库存目标，只收取本次新增的1M。脚本在42.42游戏秒的实际窗口内净增1,050,173 Block，现实耗时43.072354秒后正常返回。请求所属BepInEx与Unity日志没有新增错误；临时使用的已有 `test.py` 已在回到idle后逐字节恢复。

源码与依赖哈希、完整场景、原始报告哈希和实机请求结果见[成就验证摘要](achievement-validation.json)。实机与模型的误差仍按[模拟器验收边界](../simulator/README.md#模拟精度与验收)报告，模型数字不能替代真实游戏结果。

## C#充足炸药复核

用户已确认持续爆破取得采矿大师。当前 `block.py` 以all科技、seed=1、初始Dynamite和Block各1M运行，48.69游戏秒窗口实际净增1,044,581 Block；60游戏秒累计净增1,476,502，消耗1697份Dynamite，墙钟3.779秒。报告无运行错误、无输出截断；这是实际推进窗口，未用线性外推替代达标证据。

| 采样区间 | 初始炸药 | 区间Block净增 | 乘6的60秒估算 |
| --- | ---: | ---: | ---: |
| 0～10游戏秒 | 0 | 7,764 | 46,584 |
| 0～10游戏秒 | 1,000,000 | 145,587 | 873,522 |
| 10～20游戏秒 | 同上连续轨迹 | 137,057 | 822,342 |

前两段充足炸药窗口的外推均低于后续实际60秒产量，原因是深层爆炸存在批量结算，不能把第一段视为全程恒定速率。此前300游戏秒仅增318443的模拟使用了初始炸药为0的预设，不代表持续爆破效率；据此判定脚本必须优化的结论已撤回。满科技不等于材料充足。

本次源码、依赖、模拟器版本、初始库存、各采样耗时和原始报告见[复核证据](block-recheck.json)。

机制依据为当前游戏的 `DynamiteHat.OnDig`、`Dynamite.Explode`、`Drone.Dig` 与 `SweeperController.ClearAndScorePuzzle`；仅使用正常挖掘、爆破和正常结算。
