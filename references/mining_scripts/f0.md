# f0：八邻接煤脉开采

在游戏中运行已有的 `f0.py`。启动位置作为竖井位置：脚本向下找煤，沿同层八邻格处理煤脉，再回到竖井继续向下。

每挖到一块煤，脚本把它四周与四个对角的坐标加入待查列表。列表中的每项保存 `(x, y, z)`，同一位置、同一层只加入一次。某个分支没有煤时继续处理其他待查项；列表清空后才结束这次煤脉搜索。

相邻列如果高于目标煤层，先挖掉覆盖层，再检查目标层；目标层是普通岩石时停止扩展。覆盖层中遇到其他煤层，也把它的八邻格加入列表。已经低于目标层的列直接跳过，避免继续挖到下一层。移动使用较短的环绕路线，煤脉邻接关系限于地图内的八邻格。

这个结束条件针对八邻接相连的煤脉。它不会逐格清空整张地图，也不保证找到与这条煤脉完全断开的煤块。此前挖掘、塌方或其他地形覆盖如果切断煤脉，断开的部分可能需要另打竖井寻找。脚本不能恢复已经塌掉的煤块。

遇到不可破坏的方块、挖掘后地面没有下降或移动失败时，脚本输出当前位置并结束。移动失败时检查帽子和地形；再次运行会以当时的位置建立新竖井。停止后重新运行会重新建立待查列表。

代码入口是 `f0()`；`mine_coal()` 维护待查列表，`go_to()` 负责平面移动，`dig_block()` 检查挖掘是否推进。运行前需已解锁采矿、煤炭，以及脚本使用的函数、列表、集合、元组和导入语法。

实现依据本机游戏 `CoalFeature.Generate`、`Execution.ApplySideEffect` 中的 `GetGroundType` / `GetPosZ` / `Dig`，以及 `GridManager.ClearGroundWithCaveins`：相邻地面查询读取相邻列露出的顶层，挖掘会改变高度并可能引发塌方。已做静态审查与 Python 语法检查；使用本机游戏 API 文件检查的 LSP 为零诊断。实际矿场运行尚未验证，本地模拟器尚未覆盖地下机制。
