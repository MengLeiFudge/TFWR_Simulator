## 1. 藏宝图：去环是正常机制，原先的路线约束错误

本轮重新读取当前游戏 Core.dll，SHA256 `f0efda7c138de8028b1769c121a4b5c17b6bb538aeae5a67d1881e7c4ebd7d25`。只读反编译的 `TreasureMapController.CheckDronePosition` 明确使用路径坐标成员关系及最后匹配位置，不要求依次执行字符串中的每一次回头；到终点按原始路径长度给奖励。代码还以 `TREASURE_OPTIMAL` 奖励同层不重复访问格子。仓库源码同样可在 `references/DecompiledSource/Core/Core.decompiled.cs` 的该类核对。

因此，“保持有效通路、逐层下降、移除回环”有正常机制依据。20ms检查要求后续路径地块有效，不等于必须反复走过同一格。禁止破坏未来地块、离开通路、跳层和利用检查间隙；每次下降前仍须走到该层实际下行口。**原草稿的“完整路线不能压缩”撤销。** 当前正式脚本仍是完整路线基线，未修改。

## 2. 竹子：生长、供水、每次切花动作必须一起算

满级每次切下高度差 `h` 收益 `128h²`。三段花节，前两次各切1节再整收，均值收益依地块噪声约14962–22144；不能把所有地块都按最大高度16算。竹子不能感染，不能用肥料催长；本榜禁止dig，珍珠岩不作为免费可达的增益。水留在地块上，重种不会每株都从零重新浇四桶。

以两类噪声地块各半作敏感性输入，下面是**只有生长的理想容量时间**，尚未计实际作业，绝不是完整成绩：

| --- | ---: | ---: | ---: |
| 第一花整收 | 2709 | 1046 / 903 | 321 / 183 |
| 第二花整收 | 8896 | 649 / 560 | 222 / 115 |
| 第三花整收 | 18553 | 470 / 405 | 174 / 84 |

供水按25.6桶/秒、每桶+0.25水量、期望每秒衰减约1%积分。794株三花路线即使完美用水，也需要约174秒的生长容量；1024株理想满植约161秒，512株约193秒。满植未证明可在合法悬浮高度下廉价穿行；这些数不能直接视作可实现时间。

## 4. 金字塔：少拆原来的塔，比重建快得多

奖励为`4s² Power`，还要扣操作耗能。原生塔只侵蚀3–6列，完整塔体积 `V=1²+3²+…+s²`。均匀侵蚀的理论原始缺块均值约 `4.5V/s²`：边长13约12块、19约17块、27约23块。当前多机历史首个13塔却需补172块，说明找边界和清理过程制造了大量额外缺口；不能把现有“沙修复”标签等同于已经保住原塔。

| 路线 | 完整预算 | 判断 |
| --- | --- | --- |
| 全彩块重建 | 体积随边长近似立方增大，奖励仅平方；单机现3648秒 | 可作保证成功回退，不作首选 |
| 当前按层派工补沙 | 历史133次收获、69244次place、22864次spawn；均摊每塔约520次place | 多次全场扫描和破坏后重建为结构问题 |

## 5. 炸药：重做求解器与工作分派，奖励按剩余合格雷数平方算

满级整盘理想奖励 `16×(n²+安全格数)`。32×32约138雷，每盘318880，10M约32盘；8×8约9雷，每盘2176，100k约46盘。不能把小盘解得快直接等同于单位时间产量高。正常挖Soot提前结算只计符合邻域条件的剩余雷；不能按全部剩余雷计奖。

| 强推理/有限枚举 | 只在省下的猜错成本大于枚举解释器成本时调用 | 先做廉价单约束与差集传播；禁止无界枚举 |
| 缩小世界、用一台机做大盘、阶段并行 | 缩盘显著损失平方结算；一台机大盘可能省同步但增加动作关键路径 | 均保留比较，不预设32机一定更快 |
| 第一盘筹弹后用爆破钻清覆盖层 | 满级已有该科技，库存可从首盘获得；只有一台机能戴钻。钻也会引爆扫雷层 | 只能作为独立危险边界候选；必须证明能在不炸坏棋盘的高度停止，暂不算入主预算 |

**优先级第四，先看单机增量求解，再判断共用哪些数据结构。** 清覆盖层只是成本的一部分。

## 6. 蘑菇：优化配对率和搬运距离，而不是只换分区原点

满级每成功同色合并16，目标需15000/1875次成功配对。push单项理想成本多机15.4秒、单机61.7秒。旧单机1226.892中移动501.139、挖掘395.414、解释器229.524、push65.153。真正的配对动作并非主耗时。

| 路线 | 预算与限制 | 判断 |
| --- | --- | --- |
| 当前局部贪心、固定分区 | 多机558、单1165实测 | 保留基线；分区平移已无收益，停止微调 |
| 保留地形，利用相邻低一层接收柱，局部颜色索引 | 单机每对若平均1–2次额外dig、1–2次move，另加push及60–110秒准备/规划，按dig约0.05秒则约277–483秒 | 可研究263–411量级；配对率必须支持这些动作数，不能假定每格都有匹配 |
| 分层匹配后批量执行，工人常驻、边界交换任务 | 多机每对2–4dig、2–4move，dig约0.05秒，另加25–75秒准备/解释器：约118–246秒 | 有量级潜力；失配、跨区冲突和低接收柱准备可能推高到300秒以上 |
| 长距离搬运到颜色仓库 | 提高配对率，但单机每对多走4步就增加247秒，多机理想增加62秒 | 仅就近积累，远距离全局归仓不优先 |
| 先整平、按行/棋盘消除 | 相同高度不能直接push，目的柱必须低；预挖可能丢掉待配颜色 | 不能按二维消消乐估算，须画三维高度变化 |
| 低配对率提前换层/clear；小场高配对率 | `每片收益=16×成功配对数`，把剩余颜色的边际收益与再开片准备比较 | 有界阈值候选；现单机34片，理论全配约13片只是容量上限 |

单层相邻同色概率约1/6；同列相邻层不会同色。这两个约束必须进入规划。当前没有配对率证据支持必达138/263，保留为探索方向，不承诺前排。

## 7. 稻米：已经接近动作主导，优先级低于上述结构问题

满级每收128，多机需15625次、单机782次。若每次收获配一plant、一harvest、一move和一块硬度2的dig，理想动作成本多机86.3秒、单机138.3秒。它是给定访问模式的成本，不是所有算法的严格下界。

| 路线 | 完整预算 | 判断 |
| --- | --- | --- |
| 当前两层流水 | 多172.606、单174.566实测 | 可靠基线 |
| 单层快重生 | 少跨层调度，但反复找Clay、丢掉水量和在途成熟 | 初始准备约20秒量级，频繁重生可能吃掉全部收益，需摊销 |
| 连续多层、紧凑周期路线，每格少一次往返 | 多机86.3加准备/等待/解释器约25–45，约111–131秒；单机138.3加5–20，约143–158秒 | 最接近已知前排的普通动作预算；须让实际操作数达到该访问模式 |
| 挖掘/种植/收割固定分工 | 总动作不减，可能减少等待也可能增加交接；稻米成熟约6秒 | 仅在关键路径缩短时采用，不能默认除32 |
| 水量用于最慢一批、错峰播种 | 水量有限，降低同步等待；clear会丢地块水量 | 配合路线，不当免费全田5倍速 |
| 肥料、感染切换 | 催熟可能减少等待，但有肥料供给、感染减产及恢复成本 | 在动作主导区间通常不划算，保留净吞吐公式而不先实现 |
| 缩小世界/多种作物补资源 | 小场更易等待；资源专用盘有种植限制 | 不作为无成本供给方案 |

## 8. 地下重置：重做筹资和科技路线，不能把资源榜满级能力搬进来

当前正式13559秒。修后历史seed1完整14311.509：到Speed5约3495秒，到Dynamite3约8822秒，完成最终Rice/Bamboo准备约9529秒，最后炸药约4782秒。**前置地上筹资本身已经超过#1的整轮2699秒。** 仅把最后地下函数优化几成不可能达到它。

| 路线 | 主要费用与预算 | 判断 |
| --- | --- | --- |
| 当前单机、6×6、先Speed5、无Power | 以上四段分解 | 基线，不继续在同一依赖顺序里挪一项升级 |
| Special_Soils + Perlite/Loam 高产田 | 解锁需 Rice=800、Bamboo=1000；两种地层对对应作物均为 2 倍产量 | 优先比较 Perlite 竹子高产是否能覆盖开层、挖掘、整地、成熟和塌方成本；排行榜路线不得用 Jump，先做有限时长组件对照 |
| 提高草/树/萝卜产量，早期Power，Speed3/4先下地 | Power解锁500 Carrot；Speed5也要1000 Carrot。Mining独立决定挖掘时间 | 比较“先产量/Power再速度”与“跳过部分早期Speed”，重算全链投资回本 |
| 伴生地上供给 | Polyculture1花3000 Pumpkin、倍率10；不要直接购买高等级Bone链 | 只有后续供给节省超过南瓜/伴生准备才投资；最容易迁移此前地上榜经验 |
| 先2/4机，再提高Mining和找矿覆盖率 | Megafarm1/2累计2000/10000 Gold；藏宝图1另需40000 Bamboo | 必须选择金来源，不能把多机当初始条件；一次付费覆盖后续多资源阶段 |
| 扩8/12/16盘，提高炸药单盘平方奖励 | Expand5/6/7累计1000/9000/73000 Pumpkin；普通盘密度随深度变化 | 8/12优先算回本；16不能仅看4盘就完成而忽略73000南瓜 |
| 稳定解盘/正常部分结算、选择深度密度 | 以密度0.135、Dyn3举例：6/8/12/16盘单盘224/544/1944/5784，约90/37/11/4盘达20k | 密度仅代表情景，当前6盘旧样本并非固定5雷；要乘每盘耗时和失败率 |
| 少买Dynamite等级，靠大盘；或高等级小盘 | 等级3需要额外Mushroom和Quartz，提高到等级5还要1000 Quartz | 比较前置投入与后段节省，不固定认为全升更快 |
| 早高Mining、勘探追脉、浅煤重生、Rice/Bamboo联合规划 | 已验证局部改法是可复用组件，不是完整路线证明 | 同时算挖Block副产、Iron勘探消耗、最终稻米种竹成本，避免漏筹资 |
| 爆破钻/金字塔Power/普通迷宫Gold | 钻需12M Dynamite+120k Mushroom，远高于目标20k炸药；金字塔和迷宫各有解锁链 | 钻经济性淘汰；Power/Gold两种来源仍应与向日葵/藏宝图比较 |

整轮应写为 `地上启动与投资 + 地下科技/资源 + 最终竹子稻米 + 最终炸药`。若要达到4715量级，可分配例如1000+1800+500+1400；2699量级要求更接近600+1100+300+700。**这是用于淘汰方案的阶段预算，不是已算出2699秒策略。** 目前缺前期供给与早多机的完整支付路线，不报虚假的整轮预测。下一步先手算两条有限科技路线的资源闭包，再用具体采收周期换成时间。

## 选择顺序与下一步

1. **藏宝图去环/逐层最短路。** 当前源码支持正常去环，历史公开字符串265→3次水平移动提供具体几何证据，研究成本最低。先比较完整解析与执行成本，尚不宣称整榜已提速。
2. **金字塔保塔修缺口。** 自然缺口与当前补块数差距巨大；先解决定位过程对塔体的破坏，单双机分别组织执行。
3. **矿石多机沟网截矿、单机勘探追针。** 主瓶颈和硬度底价清楚；先算访问覆盖率、无矿dig数和补铁成本。
4. **炸药增量约束与常驻工人。** 单机解释器占比提供强证据；达到每盘预算后再考虑更强推理或正常风险结算。
5. **竹子供水/密度/切花路径联合设计。** 多机有接近前排的容量依据；单机仍缺新结构，不能宣布方向已解决。
6. **蘑菇配对与高度规划。** 先用小规模纸面状态推演获得每对额外dig/move的可信范围，再选局部/跨层算法。
7. **地下Reset两条完整科技路线。** 先算地上供给、早Power/多机与扩8/12盘，复用前三项研究所得组件；不要再单点升一级后跑整轮。
8. **稻米紧凑连续流水。** 前排差距较小且预算明确，作为较低成本的后续改进，不挤占解释数量级差距的研究。

无固定提速百分比或名次门槛。每项先用参数、动作数和资源账判断是否成立，再进入实现；模型与游戏一旦有新鲜差异，先修对应模型边界。
