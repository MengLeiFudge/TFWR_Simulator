# 全作物机制与近似边界

本地脚本模拟已适配游戏公开的12种实体，其中7种可直接种植。目标是读取同一脚本，在单个seed下尽量复刻资源、随机轨迹和时间；精度门槛见[模拟精度与验收](../README.md#模拟精度与验收)。本地报告始终是 `prediction`，筛出候选后仍须真实游戏打榜。

## 覆盖范围

| 实体或机制 | 本地实现与短场景对照 |
| --- | --- |
| 草、灌木、树、胡萝卜 | 生长、地面要求、成本、成熟/未成熟收获、伴生目标及收益倍率 |
| 树木邻接 | 四邻树各使成熟时间加倍；按原版事件刷新计时，移除干燥邻树不会立即刷新，浇水/施肥/邻格成熟可触发 |
| 南瓜、死亡南瓜 | 种植编号、成熟死亡概率、死亡后覆盖重种、最大兼容正方形合并、整组删除、感染收益；2×2、3×3、6×6、7×7收益对照 |
| 向日葵 | 7～15花瓣、满10株时最大花瓣8倍收益、先收非最大再收最大；施肥感染后的Power/奇异物质分配 |
| 仙人掌 | 数字缓存、成熟、交换、排序连锁、感染收益；保留既有方法级回归 |
| 苹果、恐龙 | 恐龙帽、独立snake流目标坐标、离开苹果格时吃苹果、移动成本递减、尾巴/边界碰撞、换帽结算、子无人机结束清理 |
| 树篱、宝藏 | 独立maze流生成墙壁和宝藏、移动受墙约束、宝藏收益、再利用后迁移与开墙、移除整座迷宫、迷宫下翻地 |
| 水、肥料、感染、补给 | 水量封顶和逐次随机衰减、加速生长、肥料推进成熟、本格/邻格感染切换、周期水肥补给 |
| 科技、地图 | 原版成本和产量倍率、父科技约束、Speed/Power速度变化、Expand从1×1经1×3至32×32；第8级为22×22 |
| 多无人机 | 农田/库存共享，位置/随机流/全局变量/闭包副本独立，返回值复制，等待与清场取消 |

南瓜收益为 `边长² × min(边长, 6) × 科技产量倍率`；感染部分按原版分给奇异物质。伴生只要求目标格实体类型符合，不要求伴生作物成熟。普通装饰帽可使用，但不模拟Steam成就或外观拥有条件。

向日葵采用当前安装版本的实际行为：12株中先收非最大，再收剩余最大，仍获得8倍基础收益；不能仅凭文字说明把“曾错误收割”视为永久惩罚。当前模型按每次收割时的花朵数量和最大花瓣重新判断。

## 计时实现与待验证边界

- 成熟事件保留原版Single随机倍率、纳秒截断和同刻四叉堆顺序。`various`的实体旋转、感染外观及逐格水分抽取消耗均接入；已验证的同seed轨迹和剩余差异见[验收记录](validation.md)。
- 水分每0.1游戏秒逐格随机衰减，零水格也抽取；生长倍率改变时重排成熟事件。
- 脚本表达式和容器操作计入tick，执行器按199t批次推进，在共同操作时刻按无人机编号应用副作用。
- Power每0.2秒结算批次操作消耗；已对照向日葵首次获得及长场景耗尽，任意并发等待组合未全面验证。
- `preset=reset` 提供低科技初始场景和升级机制，不代表已验证完整Fastest Reset流程。游戏语言的非整数range、全部解锁语法门槛、极端类型组合和任意无人机竞态仍未全面复刻。模拟内部不启动嵌套simulate或leaderboard。
- 报告无统一“误差百分比”。成熟等待密集、纯计算密集、复杂竞争或候选差距接近误差时，应增加seed并交给短程实机判断。
