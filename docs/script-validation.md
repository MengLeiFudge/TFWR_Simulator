# 游戏脚本的模拟与替换准入

任何准备在真实游戏中执行的脚本，必须先用本地模拟器验证游戏语法、正确性和效率。默认使用[C#完整模拟入口](../simulator/headless/README.md)，运行前自动用原版Tokenizer/Parser检查入口及全部静态导入；`--syntax-only` 可单独检查。覆盖真实存档已有的对应文件，还必须证明效率严格高于该文件的当前版本。编译、LSP及成熟排行榜来源只能作为补充证据。游戏源码使用原版语法子集，不使用三元表达式、推导式、lambda等Python专属语法；CPython编译成功不能放行。源语言边界和错误定位见[C#游戏语言检查](../simulator/headless/syntax-validation.md)。发现旧效率记录包含非法语法时撤回放行结论，改成合法写法后重新模拟，记录新源码及报告哈希。

## 默认条件与来源

功能脚本和普通资源排行榜脚本均以科技全解为前提。Fastest Reset类排行榜按其对应重置初始科技、库存和胜利条件运行。初版不加入低科技回退、科技升级规划或兼容分支；只有用户另行提出时才扩展。

**独立功能脚本的效率对照默认其他资源库存充足。** 例如采铁时Coal、Dynamite等已备足，采石英时Iron等已备足；比较目标资源的实际净增长/实际游戏秒，不额外计入运行其他资源脚本的补料用时，也不因勘探消耗Coal/Iron淘汰候选。所有测距、移动、开挖和解释器操作仍按真实费用执行。排行榜继续严格使用其原始库存、科技与支付规则。

优先使用用户已有的成熟功能脚本。没有对应功能实现时，先从仓库多机排行榜脚本迁入已验证算法，保留并行方式、布局、热路径、关键参数和来源许可，只做持续入口及普通游戏所必需的适配。重新设计必须先有机制理由和可比较的收益证据。水、化肥由游戏自动获取，不为它们设置生产脚本。

## 同条件对照

1. 冻结当前存档对应文件、全部依赖、候选及原算法来源，记录路径、SHA256和版本。用户已移出存档保存的原功能脚本仍可作为指定基线，必须记录它与当前存档版本的关系。
2. 固定同一套科技、地图、初始库存、随机seed和计时边界。全科技应明确使用包含DLC的配置；正式排行榜按自己的场景保留规则限制。普通地形与排行榜专用地形不能混作同一场景。
3. 连续产出使用“目标库存净增长 ÷ 实际经过的游戏秒”衡量效率，初步采样可给30秒现实计算预算；预算到了就报告实际游戏时间、净增长与增长率，不为凑固定游戏时长放宽预算。例如30秒现实计算推进100游戏秒、净增1e8，观测效率即1e6/游戏秒。600游戏秒可作为统一展示窗口，但不是准入的硬要求，短段样本不能填写成已跑满600秒。
4. 恐龙等批量结算机制先完整兑现至少一个生产周期，再按实际入库净收益/周期总游戏时间比较；未结算的0库存不代表周期效率为0。排行榜模拟不要求完成整个原目标，可由已兑现周期、有效连续采样或阶段预算估算目标总时间，但必须保留实际窗口、进度、推算方法及未覆盖部分。初始化片段、未完成批次、毛产量或API数量不能单独作为有效收益。
5. 计入脚本实际执行的初始化、规划、种植、移动、成熟、无人机派发与回收、正常结算、失败与重生。功能效率按上方其他资源充足的初始条件，不另补算生产这些预备材料的时间；排行榜及重置的实际筹资、材料准备和升级仍全额计时。首次跳跃和启动优惠单列，持续入口同时核对后续循环。
6. 在已声明的有限预算内采样对照，保留原始报告和错误。正常触及计算预算的连续生产报告可计算观测增长率，并在对应研究记录中说明如何推算目标时间；预算结束不等于脚本异常失败。未结算批次、缺失关键机制或脚本错误不能作为有效更快结果。差距接近模型误差、启动成本或随机波动时，补充必要证据或修正模型，结论确定前不覆盖存档。

## 放行与记录

开始脚本实现或优化时，在任务记录中分别列出游戏语法、正确性与效率三个验收项，并写明基线、候选和依赖版本、场景、预算及报告位置。它们是脚本任务的必要步骤。静态检查完成后仍须保留正确性与效率的待验收状态；缺报告、失败或模型不支持时，按下表记录原因和后续本地工作，不能将候选标为已完成或放行。用户要求暂停时保留这些未完成项，恢复后继续按同一口径验证。

| 结果 | 仓库处理 | 真实存档处理 |
| --- | --- | --- |
| 正确且效率严格更高，证据足以区分误差 | 更新当前最快实现、效率报告和来源 | 确认idle并备份后，及时复制到对应已有文件；不等原目标完整结束 |
| 同效迁移或相同算法尚无提速 | 可保存有来源的功能实现，明确同效或待验证 | 保留现有文件 |
| 更慢、失败、模型不支持或对照不足 | 记录原因，继续本地研究 | 保留现有文件 |
| 无对应已有文件 | 保存来源及本地效率结果，优先与成熟来源比较 | 新增文件仍按存档边界单独授权 |

效率结论就近保存：排行榜归对应`docs/leaderboards/lb_xxx.md`，功能机制与对照归`docs/script-rate-validation.md`，运行速率归功能目录README。记录源算法、基线／候选版本、初始条件、seed、实际目标／窗口、停止原因、净增长、游戏时间、吞吐、模型边界和替换判断；长哈希、冻结场景和原始回执留`.codex/`，不在正式目录新建过程MD／JSON。历史来源成绩不填成当前候选结果，旧代码与淘汰候选归`references/leaderboard_history/<lb_xxx>/`。

这些规则覆盖通过 `test.py`、`simulate.py`、生成入口或其他包装执行的脚本和依赖。临时覆盖也属于存档替换。复制不要求先达到2×#1，也不启动游戏脚本；只复制目标脚本时不生成lb_start.py。排行榜游戏执行仍须满足[共用打榜方法](leaderboards/README.md)的实机门槛；批量机制须先兑现完整生产周期，不能用未结算进度放行复制。
