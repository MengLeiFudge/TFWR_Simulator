## 每榜当前思路

| 地下榜单 | 当前实现 |
| --- | --- |
| 竹子多机 | 用空中心覆盖四邻，把竹子唯一分配给相邻中心。32×32中有794株、230个空中心，由32机分区负责。低飞切花、转移高飞；前两次只切花，第三次整株收割补种。 |
| 竹子单机 | 同样采用空中心四邻，在8×8里种46株、留18个中心。单机巡回完成切花与补种，保持两次切花、第三次整收。 |
| 稻米多机 | 每列由唯一工人处理。先种首层，逐株成功收割后立即挖到下一Clay并补种第二层，让第二层成熟与首层剩余收割重叠；全体工人返回后再重生。 |
| 稻米单机 | 单机运行相同的两层流水，在收完首层前就启动第二层成长，最后回访第二层清单，减少分批等待。 |
| 矿石多机 | 每列独占，在同一片地图采用0/4/16/20四个错开井位，复用已降低地面并分摊清场、派发费用。到石英交叉层后只追实际连续Quartz。 |
| 矿石单机 | 8×8使用0/2/4/6四个井位，单机依次处理。同片多井复用，减少反复清场和覆盖层挖掘。 |
| 蘑菇多机 | 先统一工作层，再在不相交分区内做同色推送和双邻配对。空接收柱只有在两邻块同色且满足高度条件后才挖，遇新蘑菇保留；维持两格高度带和采样柱。 |
| 蘑菇单机 | 保留同色推送、双邻配对和采样柱，采用三格高度带。多机有效的空接收柱优化在单机更慢，当前单机没有采用。 |
| 炸药多机 | 唯一协调机合并公开数字，用直接约束和有限子集推理证明安全，再按列派发挖掘。只回读未知格，已知数字缓存；全体返回后合并，推不动时才有限猜测。 |
| 炸药单机 | 同一棋盘跨猜测复用数字和已证明事实；只在真正开格前清该柱覆盖层，利用零扩展自动揭露省去其他柱准备。每次清场重建状态，避免跨盘复用。 |
| 金字塔多机 | 定位Limestone基座和边界，清覆盖土时保留Sand。读回实际缺块，按完整底层支撑逐层补沙；所有工人结束后主机最后放中心顶块并收取奖励。 |
| 金字塔单机 | 清空足印后用彩块重建。清理与构造都让相邻列反向遍历，减少列尾回列首的移动。留沙方案在单机完整模型中更慢，当前保留彩块版。 |
| 藏宝图 | 定位地图，只读一次完整路线，用方向字典执行每一步。保留回头路和全部D挖掘，最后验证宝藏再收取；当前改进主要减少解释器分支费用。 |
| 地下重置 | 按实际get_cost分阶段筹资。先补给科技和Speed5，再投资Iron2、Rice5、Coal3和Mining8；Iron用付费方向勘探，Quartz用付费距离定位。Rice开启后采煤只采首16层再正常重生；末段扫雷复用缓存并按需清覆盖层，最终支付20000 Dynamite和200000 Bamboo。 |
