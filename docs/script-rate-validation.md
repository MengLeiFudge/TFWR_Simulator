# 常规速率与特殊成就验证

本轮始于2026-11-11，12日更新蘑菇、32机怪异物质与炸药，复验炸药成就依赖。用户表分别归[常规脚本](../scripts/functional/README.md#当前产出速率)与[成就脚本](../scripts/achievement/README.md#成就与运行时间)，精确数据归[script-rate-validation.json](script-rate-validation.json)。常规后续优化归[首轮持续生产记录](functional-optimization.md)和[第二轮并行优化](functional-parallel-validation.md)。这里按每项当前版本保存数据；此前Python模型和早期C#结果保留为历史，不混入当前速率。

## 条件与口径

- 当前 C# 原版语言、调度和动作模型；`preset=all`，普通32×32田，全科技含DLC、最多32机、无排行榜特殊盘面。19项可用物料各10亿；具体科技、初始库存、执行器与资源表哈希在JSON中保存。奖励帽不是全科技的一部分。
- 常规表使用seed=1。多数入口观察60游戏秒；蘑菇观察120游戏秒包含完整采集片；竹子观察450游戏秒以覆盖原500M重建边界；金字塔以增加5000能量为目标，完整运行127.346游戏秒；恐龙完整结算一轮后返回。初始化、Jump、移动、成熟、同步与结算全部计时；炸药等物料的生产时间不另计入独立入口速率。
- 速率=`实际净库存变化×60÷实际game_seconds`。用户表只列正增长，含正收益副产物；水和肥料由时间自动补给，排除。完整净库存仍保留在证据JSON内。有限窗口不能证明无限期稳态产量，材料耗尽和硬度边界会停止脚本。
- 每样本先限制10墙钟秒，四进程并行。恐龙首次在10秒预算内推进736.95游戏秒但尚未结算；仅为兑现这一完整周期，将该样本预算调为25秒，实际10.76秒完成775.38游戏秒并收取33,488,928骨头。没有把未结算的0骨头当速率，也没有将预算当实际耗时。
- 24个专用入口各执行seed=0/1/2，共72次。22个入口正常结束；另两个分别触发预期除零/栈溢出。全部小于300游戏秒，结束均只剩主机。随机机制以本次范围为预计时间，不承诺任意seed必成；失败会在预算内返回原因。
- 原始报告和逐样本源码冻结在`.codex/script-followup-20261111/reports/`、`.codex/functional-optimize-20261111/reports/`及`.codex/functional-parallel-20261112/reports/`。汇总条目保留原始路径、报告SHA256、源码与依赖哈希、实际时长、停止原因、净库存与完成条件；本轮57个样本的API计数、预算和输出摘要归[第二轮完整数据](functional-parallel-validation.json)。原始目录不提交。

本地模型没有记录 Steam 账号解锁状态。成就正确性依据原版触发条件、脚本实际动作和报告输出；不能把`finished`单独当作已解锁。小田入口结束时游戏恢复农场尺寸，结束快照可能已经回到32×32，应结合完成前的坐标/数量输出核对。故意错误入口的`state_complete=false`属于预期结果，不能用于生产效率证明。

## 常规优化

四个采矿入口统一调用`mining.mine(item, target)`：保持单爆破钻向下深入新地层，利用真实爆破掉落，省去反复重生浅田、横向追脉和稀疏开孔。每次开挖前检查库存目标与炸药；没有后台子机。`block.py`仍独立保存采矿大师的60秒库存窗口，并补上炸药耗尽检查。

| 入口 | seed=1旧速率/游戏分钟 | 新速率/游戏分钟 | 三seed提升倍率范围 |
| --- | ---: | ---: | ---: |
| 煤 | 1,360 | 15,334 | 5.63–11.28× |
| 铁 | 35,952 | 213,040 | 4.30–7.01× |
| 石英 | 17,752 | 139,904 | 4.81–10.79× |
| 石化南瓜 | 670,208 | 3,823,104 | 2.60–5.70× |

对照使用相同科技、地图、初始库存、seed和60游戏秒。四候选在三个seed下均严格更快；候选冻结结果和迁入后的seed=1结果一致。共享算法让四入口保留各自库存目标，不再维护四套相近挖矿路线。历史浅层算法来源与淘汰依据见[地下效率记录](underground-functional-validation.md)和[勘探记录](underground-prospecting.md)。怪异物质、竹子、金字塔、向日葵和炸药的后续对照、有限目标与存档部署归[持续生产记录](functional-optimization.md)。

`resources.materials`为煤、铁、石英准备2000份炸药；铁不再额外准备勘探用煤。调度验证：初始炸药为0、煤目标增加500，先生产炸药，再连续深钻至煤实际净增732，40.65游戏秒返回，全部目标达标且只有主机。库存已满足时五个入口合计0次挖掘；炸药为0时煤和建材合计0次挖掘。四个新入口的有限目标也分别正常返回。

`block.py`当前seed=1在49.37秒库存窗口内净增1,044,581建材，60游戏秒共净增1,474,855。补上材料检查后相对上一版1,476,502减少约0.11%，换取缺料时正确停止；不是新的提速结果。炸药共享求解器的可选截止时间与禁止部分结算参数继续供成就入口复用，常规调用正常结算；当前同时复用固定分区几何后，首60秒390608炸药，完整两盘速率比11日基线提高1.4%～1.6%。

蘑菇各区只派工一次、连续处理整片，普通田找层范围保持不变；120秒三个seed速率提高6.5%～10.3%，seed1为27888/游戏分钟。怪异物质改为32机每机半行8棵树并往返巡视，三个seed提高78.6%～84.4%，seed1为912588800/游戏分钟。竹子两种筛选候选没有稳定改善，保留11日版本。有限目标、失败恢复和实际部署见[第二轮对照](functional-parallel-validation.md)。

## 成就筛选与修正

Steam中文schema共111项，分类结果为：29项专用成就对应24个入口；76项常规复用；2项排行榜复用；4项手动科技/UI操作。[完整清单](achievement-audit.json)逐项保留官方名称、说明、类别和入口，[来源事实](../references/achievements/steam-schinese.json)保存API ID及抓取信息。

新增8个入口：`acrobatics`、`block_builder`、`prospector`、`healer`、`giant_pumpkin`、`treasure_hunter`、`rice_terrace`、`dynamite_expert`。不再将普通分区南瓜、小迷宫、流水收稻或部分炸药结算认作对应特殊条件。

| 边界 | 原版依据 | 本轮证据 |
| --- | --- | --- |
| 摩天大楼是+150 | `Native/Farm.cs`的PlaceBlock在内部depth≤-150时判定；游戏get_pos_z为相反号 | 9机同时垫高3×3田，输出高度150，5.734游戏秒；不再向下挖-150 |
| 最小可指定田边为3 | `Native/Farm.cs`的GridManager.SizeLimit仅接受大于2的缩田值 | 不使用无效的set_world_size(1)；单柱会因高度差触发放置上限 |
| 时装秀看同时在场的不同帽子 | `Native/Farm.cs`的ChangeHat统计存活无人机帽子 | 使用普通Brown/Gray/Green/Purple和Mining帽，2.169秒结束并回收；不依赖奖励帽 |
| 泥泞农场要求整田水位达标 | Steam写“超过0.5”；原版`Native/Farm.cs`的UseWater实际检查所有格≥0.5，水随游戏时间蒸发 | 32列并行，每格4水；结束全田最低含水量0.90438，4.258秒 |
| 巨型南瓜需32×32整体 | `Native/World.cs`的Pumpkin收获检查尺寸 | 三seed整田收获均有实际南瓜入库，13.0–14.5秒；正常16区算法不替代 |
| 宝藏猎人需要整田迷宫 | `Native/World.cs`的Treasure收获比较mazeSize与WorldSize | 生成32×32迷宫，三seed收获金币32768，20.9–70.2秒 |

大金字塔仍复用常规修塔：原版`PyramidFeature.Generate`可生成29×29塔，常规算法按实际边界修补；只是出现时间随机，不能承诺5分钟。彩色金字塔保留已经验证的6×6田内5×5原生塔方案：生成器最小底边5，有效体积35，不能自行用3×3人造塔代替。

## 验证与交付边界

所有游戏入口及实际导入模块由C#原版Tokenizer/Parser前置检查后执行。两轮常规优化均没有改动C#代码，复用未变的执行器。12日修改的三个入口LSP无错误或警告、16项hint。静态复核截止时间、句柄回收、库存目标、材料不足、固定几何与盘面事实分离；对应报告保存当前源码/依赖哈希。炸药成就依赖更新后重跑三个seed，仍在63.40–239.73游戏秒完整解盘并回收全部子机。表格来自冻结报告，成就名称与分类保持原官方中文映射。

第一轮怪异物质、竹子、金字塔、向日葵、炸药，以及第二轮蘑菇、32机怪异物质、固定分区炸药，均冻结仓库与真实存档版本、完成同条件对照后，确认idle并持同名状态锁备份，只覆盖Save0已有对应文件。没有启动真实游戏，也没有新增/删除存档文件或生成运行入口。第二轮没有覆盖竹子；其他常规入口保持原值。新成就文件仍不直接添加到Save0，临时执行按项目约束适配已有入口。部署摘要与模型边界分别见[首轮记录](functional-optimization.md)和[第二轮记录](functional-parallel-validation.md)。
