# 游戏解释器计费与节时写法

写策略时按本页选择等价且更便宜的写法。先保证动作、收益和状态正确，再计算初始化、循环主体与恢复成本。**0t只描述指定操作，不代表整段算法免费。**

## 常用操作费用

| 操作 | 当前规则 | 写法选择与边界 |
| --- | --- | --- |
| 普通变量读取、赋值、解包 | 0t | 解包已经存在的元组免费；新建元组仍计1t |
| 一元`not`、正负号 | 运算本身0t | 操作数求值另计；仅在语义等价时用`not count`代替`count == 0` |
| `if not count` / `if count == 0` | 对普通数值分别1t / 2t | 1t来自分支；`None`、空容器等不能一律按数值零处理 |
| 函数定义 | 每次执行定义1t | 生成很多静态函数仍有初始化费用 |
| 直接静态自定义函数调用 | 分派0t | 函数体、参数求值、默认参数求值另计 |
| 自定义函数别名、重新赋值、条件定义后调用 | 分派1t | `f = f`也会失去该名称的静态标记 |
| 内置函数经变量或绑参调用 | 不额外收取自定义函数的分派费 | API自身费用不变，例如成功`move`仍为200t |
| `get_tick_count()`、`get_time()`、`quick_print()` | 0t | 输出参数中的运算照常计费；`print()`约1游戏秒 |
| `str(value)` | 转换本身1t | 没有统一的“字符串操作每8字符收费”规则 |
| 字符串作字典/集合键 | `max(1, L // 8)` | `L`为UTF-16代码单元数；元组键递归累加各元素大小 |
| 字符串包含`part in text` | `len(text)` | 按全串长度计费，包括提前命中；支持子串，空串成本0t |
| 字符串`left + right` | `max(1, len(left) + len(right))` | `+=`按结果长度收费，空串加空串为0t |
| 字符串索引 / 切片 | 1t / `max(1, 结果长度)` | 长度与索引按UTF-16单元；非整数及全部切片边界未全面验证 |

`not`节省的是一次比较，并不是删掉分支成本。需要保留真假含义，例如“无人机句柄不存在”和“计数为零”应分别确认返回值约定。

### 字符串键：先算是否复用

社区原文把许多字符串操作概括为`ceil(len/8)`，但没有列明操作清单。当前源码中，键大小使用整数除法向下取整：长度9、15、16、24分别计1、1、2、3t。字符串转换、拼接、包含、索引各有自己的规则，不能套用该公式。

游戏`str((12, 31))`产生`"(12,31)"`，中间没有空格，长度7。已有两元素数值元组的字典查表为2t；每次先`str(pos)`再查表同样为2t。预先转换并复用字符串键时，后续每次查表才降至1t。新建元组、建立字典和生成字符串的费用另计。

实际覆盖了长度0、1、7、8、9、15、16、17、24的字符串键，以及8个emoji组成的16个UTF-16单元键。容器字符串使用单引号包住字符串元素，重复列表/字典引用显示`...`。完整浮点格式化与依赖地区的字符串排序尚未全面对齐；策略键优先使用已验证的整数坐标或字面量，不把未验证格式用于费用预测。

## 函数绑参与启停

游戏的`value.function`把`value`绑定为该函数的第一个参数；普通值右侧的函数按词法名称查找，不是Python对象方法反射。再次绑定会替换旧首参。下面的内置调用没有额外动态分派费：

```python
north = North.move
north()                    # 正常移动并支付200t
north = get_tick_count
north()                    # 0t空操作，不执行移动
north = North.move
```

自定义函数有不同的绑定费用：`value.f()`在`f`静态时分派0t；先`bound = value.f`再`bound()`，别名调用分派1t。函数体没有因此免费。不能拿内置函数别名的费用套用到自定义函数。

`from helper import f`会保留模块导出的静态标记，因此可恢复被禁用的静态入口。首次导入必须支付整个模块初始化；同一无人机后续导入不重复初始化。动态模块别名的属性读取本身不加tick，但从它取得的自定义函数调用不再静态，分派1t。

本地模型支持同目录`import helper`及显式`from helper import f`，报告保存模块源码哈希。通配导入（类型提示的builtins导入除外）、模块属性赋值等尚未支持的路径明确拒绝，不按0t跳过。子无人机的模块初始执行及作用域复制已对照；不得把跨无人机模块缓存异常当作优化依据。

## 固定槽位与引用状态

固定容量队列可以把运行时列表索引和移动换成普通变量赋值。以下只展示**已知有三个有效元素**时的一次出队；调用方负责空队列、有效长度、容量与溢出：

```python
q0 = 3
q1 = 2
q2 = 1

def pop_oldest():
    global q0
    global q1
    global q2
    result = q2
    q2 = q1
    q1 = q0
    q0 = None
    return result
```

函数定义计1t，直接静态调用时上述出队主体0t，返回旧队尾1。变量状态可存引用或整数；若增加`count -= 1`、判断或列表访问，需要把这些费用加回来。游戏每条`global`只接受一个名称，不能写Python的`global q0, q1, q2`。

固定槽位适合已知容量的蛇身、有限状态或小队列；不保证任意长度容器免费。旧社区示例存在保存旧值却返回新头部的问题，不能原样复制。`cactus_ztc.py`预建-10至10的有限引用节点，通过解包切换后继、前驱和取负引用；构建与连接节点先付费，边界饱和，不能当作通用整数运算。

## 静态格点函数与策略应用

`walker_zero.py`为3×3每格生成静态函数，访问格子时将入口改成空操作，并按预排顺序递归访问其他格。它依赖同一场有限图遍历的不变量。新一轮搜索的入口恢复、图变化、初始化、真实移动和代码解析开销都必须计入。

- Sunflowers：可用静态格点函数或预建引用降低距离计算和规划开销；仍需核算成熟、同步和移动。
- Maze：固定队列与静态邻接入口可能减少BFS索引；新开墙信息仍须真实探测。
- Dinosaur：固定槽位可降低身体维护成本；必须保留合法移动、尾部释放和进展保证。
- Reset：先保持解锁与供料链收益，再压缩密集执行的已验证操作。

写新候选时，在设计阶段直接选用等价的便宜写法；不必等算法完成后故意保留昂贵表达式。研究优先级仍由主瓶颈决定。生成代码要限制大小，初始化/重置与运行费用分开报告，现实解析耗时不能冒充游戏tick。

## 合规与复核

只使用游戏预期机制。不利用200tick结算窗口重复领取同一迷宫宝藏，不依赖模块缓存bug、无人机副本纠缠等异常获益。以同版本合规基线和动态阶段目标比较收益，公开排名仅作参考，具体见[共用筛选规则](README.md#固定效率闭环)。漏洞修补时间来自用户说明，未作为已核实公告。

应用新写法时，保存实际执行源码和依赖哈希，用固定输入对照返回值、状态与累计tick；确认初始化和恢复都已支付。若遇到未覆盖语义，先补有界实机对照，不能以估计0t放行候选。
