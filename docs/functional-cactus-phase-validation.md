# 常规仙人掌：就地收割与行列成本

2026-11-12。采用就地收割及有限目标提前结束，保留原来的窗口缓存、行列排序和树形派发。全科技含DLC、32×32田、32台无人机、19项资源各10亿，其他材料充足。24份报告均预设10墙钟秒，最多两例并行，实际最长0.885墙钟秒；所有入口及实际依赖均通过C#原版Tokenizer/Parser前置检查。

## 当前入口

`cactus.cactus`先检查目标库存。需要生产时，仍先铺田并排好全部行，回收所有行工人，再排全部列并回收列工人；随后直接在主机当前位置收割整田。达标立即返回，仍需下一批才执行原有`goto(0, size - 1)`。排序、布局、资源检查和下一批的起点不变。

原实现无论是否已经达标，都先回固定角落再收割。原版`Cactus.Harvest`调用`Pop`，后者沿成熟且满足`IsSorted`的邻株传播；当整田1024株全部成熟有序时，收割起点无需是固定角落。这里没有提前收割局部区域，仍以一次完整33554432入库和收后全田为空验证。

该改动让资源更早入库，并省去有限目标最后一趟返回。持续循环仍保留下一批的原有路线，不把有限目标收尾收益写成永久稳态提速。

时间单位为游戏秒。行阶段含启动、铺田、定位、排序和等待；最后一列是相邻阶段最后一次wait返回时点的差，含列派发、定位、排序及少量调用开销，不是纯交换时间。列交换约占全田交换的35%～40%，并非可以忽略的小尾部；总动作数也不能除以32直接当作共享完成时间。

从真实轨迹恢复三个seed共96条行的播种后数值，逐交换重放原三格窗口序列全部一致。若规划免费、只前往发生交换的窗口并恢复原终点，行排序总移动分别可由5783/5729/5634降至5123/5127/5070。但最慢排序行的move+swap最大值只由456/488/460降至435/476/452。对每次交换的两个端点再作贪心选择及二态最短路，得到相同的总移动值，没有额外省步空间。这些仅为固定交换序列的几何预算，未计规划、缓存及执行成本，不能作为效率成绩。
