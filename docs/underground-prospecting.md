# 普通功能采矿：煤与铁勘探对照

2026-11-08。仅运行本地模拟。独立功能脚本的其他资源均视为充足，只比较目标资源实际净增长/实际游戏秒，不补算Coal、Iron或Dynamite的生产用时。该约定已写入[脚本验证规则](script-validation.md)；排行榜继续使用各自原始库存与科技。

## 探测返回什么

- `prospect_iron()`支付1 Coal，返回最近铁矿的水平引导方向，或None。方向按非环绕坐标给出；选择目标时考虑目标柱尚未开挖的覆盖深度。None可能表示已经对齐目标柱，也可能表示搜索范围无矿，收入仍须由实际开挖确认。
- `prospect_quartz()`支付1 Iron，返回当前位置到最近石英的三维直线距离，或None。原版搜索范围32格。例如返回10，表示最近石英距离当前位置10格，不能据此直接得到x/y/z或水平移动方向。
- 同一位置开挖后，最近矿和地面高度都可能改变，重新探测即可。比较相邻位置的距离时须包含其实际高度；三点几何解也只作为下一口钻孔候选，不直接记作产量。

原版依据为 `Drone.ProspectIron`、`Drone.ProspectQuartz`、底层 `FindClosestOre*`，本地对应 `World.api_prospect_iron`、`api_prospect_quartz`、`Underground.closest_ore`。没有为这些候选改模拟器规则。

## 铁：采用煤方向引导与已露矿追脉

当前 `iron(target=-1)` 首次Jump到铁附近，优先开采脚下或相邻已露Iron；没有可见矿时调用 `prospect_iron()`，沿方向移动或在对齐柱用主机爆破钻开挖，地形变化后重查。每片最多512次追矿/开挖动作，600游戏秒、绝对深度128保护；连续16口无收益换田，连续8田无收益返回。始终以实际Iron库存判断目标，无参持续运行。

相邻地面高低会影响欧氏距离，单纯找距离更小的邻格可能困在深孔；三点法则要承担最近矿变化、镜像解和额外测距移动。并行版还包含主机准备、子机普通挖掘及最慢工人回收。本轮已将这些费用纳入完整启动样本，下一轮需先区分哪个阶段仍值得改变，不能直接从无人机数量推算倍数。

## 不同方向的取舍

| 方向 | 收益来源与置信度 | 当前判断 |
| --- | --- | --- |
| 煤方向追铁、可见矿直接追脉 | 用公开方向减少无收益钻孔；三seed均改善，置信度较高 | 已迁入铁功能 |
| 单机测距接近或三点定位 | 避开无关柱，但移动和推理增加；本轮代表未获收益 | 保留负例，不扩大枚举 |
| 主机准备、32机各自采矿 | 隐藏覆盖层与矿块硬度时间；需要同时控制准备、重复追矿与收尾等待 | 四个代表均未改善，继续寻找结构收益，不调整消耗预算 |
| 32机各自独立世界 | clear、地层和塌方共享，世界不独立 | 机制不成立，立即淘汰 |
| 先前20k多机榜三锚点 | 场景无初始Iron、不能Jump/爆破，与普通全科技功能不同 | 旧负例只约束该榜具体实现，不外推本页 |
