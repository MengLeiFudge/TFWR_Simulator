# lb_maze

## 榜单目标

- 目标资源：`Items.Gold`
- 多无人机路线
- 当前脚本目标数量为 `9863168`

## 结算机制说明

- 迷宫榜的收益核心不是普通 harvest，而是“生成迷宫 -> 找到 Treasure -> 对 Treasure 重复使用 `Weird_Substance` -> 在合适时机收割”。
- 迷宫大小的基本规则是：
  - 对 Bush 使用 `use_item(Items.Weird_Substance, amount)`
  - 未升级迷宫时，`amount = n` 就会生成 `n x n` 迷宫
  - 每次迷宫升级，宝藏金币翻倍，但所需 `Weird_Substance` 数量也会翻倍
- Treasure 的基础收益是：
  - `迷宫面积 * YieldFactor`
- Treasure 最多可以被重新定位 `300` 次
- 因此一个迷宫在吃满重定位次数后的总量级，可以近似看成：
  - `迷宫面积 * 301 * 32`
- 套回当前 leaderboard 目标：
  - `4x4` 迷宫面积是 `16`
  - `16 * 301 * 32 = 154112`
  - 要达到 `9863168`，大约要重复 `64` 次
- 但如果直接做 `32x32` 全场迷宫：
  - 面积是 `1024`
  - `1024 * 301 * 32 = 9863168`
  - 也就是理论上只需要完整做成 `1` 次
- 从这个公式反推，当前多迷宫榜非常像：
  - `4x4` 路线是“小迷宫高频重复”
  - `32x32` 路线是“大迷宫一次到位”

## 通用注意事项下的榜单特化

- 这个榜单的主收益来自“迷宫生成 + 连续 use_item + Treasure 结算”的流水线
- 真正要优化的不是单次 harvest，而是：
  - 哪些格子负责开迷宫
  - 哪些格子负责持续 use_item
  - harvest 时机是否足够接近极限
- 世界大小、格子分工、启动时序是绝对核心变量
- 但这条流水线有一个当前版本必须正视的时序事实：
  - 旧版 `main2-main8` 的核心假设是：对 Treasure 使用 `Weird_Substance` 后，宝藏会立刻移动到下一个位置
  - 现在这个假设已经不成立
- 反编译源码 `Treasure.RepositionTreasure(...)` 可以确认：
  - 对 Treasure 使用 `Weird_Substance` 后，会先 `repositioning = true`
  - 然后 `StartTimer(CompleteRepositioning, sim.OpDuration * 200.0)`
  - 也就是新宝藏不是同步出现，而是延迟一段动作时间后才真正放到 `nextPos`
- 这正好可以解释为什么旧版 `main2-main8` 在新版里会大量提前收获：
  - 它们的判断逻辑默认“宝藏已经立刻到下一格”
  - 但实际上还在延迟中
  - 于是会在还没够 `300` 次前就把 Treasure 收掉

## 当前版本结论

- `main1`
  - 大图墙跟随，已经被证明远慢
- `main2`
  - 左下 / 右下双 4x4 分区，每格 1 机
- `main3`
  - 5x5 + 2x2 + 1x1 的混合分区，比 `main2` 略快
- `main7`
  - 4x4，每格 2 机，其中较慢的 5 格兼职开迷宫
- `main8`
  - 当前默认路线；仍是 4x4 每格 2 机，但所有格子都兼职开迷宫，继续压时间
  - 但 `main2-main8` 那一整代的文件内时间目前只能当历史旧版本数据看，不能再当现行实测
  - 它们的主要问题很可能正是“提前收获 Treasure”
  - 2026-04-24 复测：45 秒窗口无完成轮次，请求 `52` 被停止后结果页能自动确认

## 失败对照

- 大图迷宫 / 墙跟随式探索
  - 已明确不是榜前方向
- 过度不均匀的分区
  - `main2`、`main3` 虽比 `main1` 快很多，但仍被后续更均匀的 4x4 双线程路线超过
- 旧版 `main2-main8` 的“立即换位”假设
  - 这条假设在当前版本下已经失效
  - 继续沿用会导致 Treasure 在没满 `300` 次前就被收掉
- “迷宫必须重复使用才值”
  - 这条线也不成立
  - 官方说明已经明确写了：重复使用迷宫得到的金币并不会比直接收获并重新生成更多
  - 只有当额外信息和捷径能让你更快到 Treasure 时，重复使用才有意义

## 下一步优化方向

- 先确认当前版本下 `Treasure` 延迟换位后的正确收获时序
- 再重新评估 4x4 双线程是否仍值得继续救
- 重点看：
  - 旧 4x4 双线程路线在修复提前收获后能回到什么水平
  - `32x32` 一次到位路线是否比 `4x4 * 64` 的重复路线更有希望
  - A* / 探图路线在真实迷宫里的信息收益是否足够抵消调度成本

## 候选策略方向（猜测 / 待验证）

### 方向 1：保留 `4x4`，每格 `2` 个无人机，但先修复 Treasure 提前收获

- 核心思路：暂时不推翻旧主结构，先把 `main2-main8` 里假设“宝藏立刻换位”的收获逻辑修正到当前版本
- 主瓶颈：当前 10 分钟以上的主要嫌疑不是大方向完全错了，而是收获时序错了
- 可能更强的原因：如果瓶颈真的主要来自“没够 300 次就提前收”，修正时序后这条结构可能还能重新竞争
- 优先探针：
  - 旧 `main2-main8` 在新版里提前收获的真实触发点
  - 修正后 4x4 双线程路线的实测时间回升幅度

### 方向 2：`3x3` 区域探图 + 改造版 A* / 最近无人机抢宝藏

- 核心思路：把全图分成 `3x3` 的 `9` 个区域，每区放 `2-3` 个无人机，先到位探图并持续收集迷宫信息，谁离 Treasure 最近就谁去
- 主瓶颈：旧 4x4 路线本质上是在绕开“真正走迷宫”这件事；一旦时序改了，它的捷径可能不再成立
- 可能更强的原因：如果新版 Treasure 延迟与迷宫信息传递更重要，那么“谁最近谁去”的路径策略可能比纯定点流水线更强
- 优先探针：
  - 3x3 区域探图后的平均到宝藏步数
  - A* 路线在真实迷宫里是否比固定职能路线更快

### 方向 3：直接押注 `32x32` 全场迷宫一次到位

- 核心思路：既然 `32x32` 一次做满理论上就等于整个目标值，那就直接把重点放到“如何尽快完成一次全场迷宫并拿满 301 次”
- 主瓶颈：大图迷宫导航成本极高，旧版 `main1` 之所以慢就是这个问题
- 可能更强的原因：从收益公式看，`32x32` 才是唯一能“一次到位”的路线；如果能把路径规划问题解决，它的上限显然最高
- 优先探针：
  - `32x32` 全图迷宫下的平均寻宝步数
  - 大图探路成本是否会完全吃掉“一次到位”的理论优势
