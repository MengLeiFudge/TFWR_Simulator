# 常规脚本的持续生产优化

本页记录2026-11-11的第一轮优化；蘑菇、32机怪异物质与炸药固定分区的12日更新见[第二轮对照](functional-parallel-validation.md)，当前速率统一查[常规产出表](../scripts/functional/README.md#当前产出速率)。以下保留首轮结论和历史版本。使用同一C#原版执行器、全科技含DLC、普通32×32田，19项材料各10亿。每例10墙钟秒、最多4进程并行；速率均为实际入库净增长/实际游戏时间，包含初始化、移动、成熟、重派和结算。完整初始条件、脚本/依赖/模型哈希、报告摘要和部署记录归[首轮数据](functional-optimization.json)；原始报告与冻结源保留在`.codex/functional-optimize-20261111/`。

`weird_substance.weird_substance`只在开始清田。工人从当前树与真实伴生关系恢复苗圃，保留未收获的合格树；已收获的树重新种植后仍重新筛选。每60游戏秒回收一次工人，共用截止时间保证失败后其他工人也能退出。125游戏秒样本覆盖两次回收和恢复，仍只有一次clear；16份初始肥料的缺料样本在6.99游戏秒返回，有限目标及已满足目标也正常返回且只剩主机。

`bamboo.bamboo`保留原500M切收批次，批次完成后只重派工人，不再清田或重新筛选已经合格的花节。首次建立竹林仍有随机筛选成本：seed1首60秒产出4175.40万，低于仓库基线4402.75万约5.2%；持续450秒才兑现复用收益，不能将长期提升套在首分钟。

`power_pyramids`迁入`lb_pyramids.py`的并行基边探查、三列邻格采样、就地清土补缺和树形维修。仍由主机独占一座塔，底层支撑齐备才推进高层，最后放置中心顶块。清理包含几何高度上限，高于公式表面的Sand也会挖去。普通田保留Jump、浅层爆破及有界找塔。增加5000能量的三个seed完整耗时从205.253/136.908/101.955降至198.211/127.346/89.919游戏秒，结束均只有主机。首60秒窗口恰好截断在不同找塔阶段，不能据此代替上述完整目标对照。

`power_sunflower.water`每次补4份水，同一次动作提供较长的湿润期；完整周期后复用土壤和水位。有限目标由`finish_wave`在整波9个瓣阶段全部同步后统一决策：0号组多收一格Grass表示停止，或用一棵临时Pumpkin的Carrot消耗表示继续，避免各组读取目标的时刻不同而退出失配。没有新增补料品种。补1000能量从164.864降至16.810游戏秒；补50000能量在89.737游戏秒返回，32机全部回收。Wood/Water初始为0的有限样本也能正常结束。这些是目标完成时间，不把减少超额生产宣称为同倍率的产出提速。

`dynamite.make_near`把1024格的固定邻接表分段并行构造，再按原索引拼接。区域安全推理、事实合并和每盘结算保持原实现。同样两盘、同样收益，三个seed均省3.176游戏秒；这项收益来自启动，不声称每盘求解都变快。首60秒表格仍如实显示390560炸药，较仓库基线390064只多约0.13%。

## 未迁入的候选与观测边界

- 竹子每60秒回收的候选会打断各行切收节奏，300游戏秒净产出449543808，低于基线488727296，已关闭。
- 蘑菇采完继续向下找的48格候选，在120游戏秒下seed0/2低于基线、seed1较高；扩大至64格后仍有seed0明显退步。保留普通田原有换田策略。
- 蘑菇减少重复柱顶读取的缓存候选，在120游戏秒下三seed分别获得50352/50848/48656，对应基线50320/50848/47872。一个seed同效，最大提升约1.6%，未作为稳定提速迁入。
- 向日葵跨周期样本保留10墙钟秒预算，最多推进至180.382游戏秒，已进入第二周期但未完成新增110000能量目标。其中有不完整状态快照，全部单列为预算观测，不参与效率对照或完成结论；没有放宽预算补跑。

截至首轮，蘑菇保留原版，不能据这些局部尝试宣称其吞吐已提高。后续已采用的常驻分区与末层取舍见[第二轮蘑菇对照](functional-parallel-validation.md#常驻采集与32机苗圃)。

## 版本、存档与静态检查

仓库基线和实际存档分别冻结。真实存档竹子是更早的星形布局，首60秒2492.15万；炸药和向日葵也与仓库版本不同，均单独对照，没有拿仓库源冒充存档源。怪异物质、金字塔存档与仓库基线相同。

五个已迁入文件通过当前游戏语法、对应有限目标、已满足目标以及效率对照后，于idle498持同名状态锁备份并覆盖已有对应文件。其他Python文件及文件列表不变，没有创建运行入口或执行游戏。正式源与冻结候选AST一致；金字塔seed1完整目标还使用正式源重新生成报告。

`dynamite_expert.py`依赖更新后重跑seed0/1/2，分别在63.246/203.783/239.344游戏秒完整解盘并只剩主机。成就源码和5分钟上限不变，关联报告已刷新依赖哈希。

本轮没有修改C#，复用未变的执行器；LSP无错误或警告，36项hint为未用变量及外部类型桩造成的不可达分支。模型与API组合的精度限制仍遵守[模拟器验收](../simulator/README.md#模拟精度与验收)，本地结果不代替真实游戏精度或Steam到账验证。
