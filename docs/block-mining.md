# 建材连锁爆破

入口为 [block.py](../scripts/functional/block.py)，保留 `block(target=-1)`：无参持续生产，传入非负库存下限后在达标时回收子机并返回。需要全科技、普通32×32田、32台无人机，以及预备炸药和胡萝卜；入口会清场。

## 爆破组织

田内按四格间距布置64个炸药网点，每台无人机负责相邻的两个网点。工人常驻同一片田，等待上一轮爆破后重新布置。每台机在末个网点旁搭一格土台、翻土并种一株向日葵作为就绪标记。主机从自己的向日葵格戴唯一的爆破钻点火，工人同时确认自己的标记消失、Block库存高于布药前，才布下一轮。

爆破钻调用 `Dynamite.Explode(..., collectDrops: true)`。爆炸触及已种炸药的地面时补充能量，继续传播并收集实际清除块的掉落。不能直接下挖种有炸药的格子：实体的 `Dynamite.OnDig` 会先执行不收集掉落的普通爆炸。未触达和塌方消失的块都不计入产量。

每轮消耗64份布药加1份钻头炸药，共65份Dynamite；32株标记各消耗当前 `get_cost(Entities.Sunflower)` 的胡萝卜种子，现有资源表为每株1份。每田最多16轮，完整材料储备为1040份Dynamite和512份Carrot。每轮先放置32块土台，放置支出计入实际Block净增长；启动库存不足32时先有界手挖。`resources.materials(Items.Block)` 从 `block.ROUNDS_PER_FIELD` 和当前种子成本准备材料；入口按炸药和种子均能支付的轮数执行。

## 同步与退出

主机在派机前冻结Carrot库存。所有工人只种自己唯一归属的网点和标记，地下爆破不产Carrot；本轮32株标记的种子消耗完成后，主机才点火。原生炸药层会额外发放Dynamite，因此Dynamite库存只用于支付预算。工人在自己的向日葵格同时等待标记消失和Block增长，避免原生炸药自爆造成提前推进。Block比较基线在布药前采集，保证最后一台机的种植动作尚未返回时，主机点火也不会让它漏记本轮增长。

调用者需要独占本次执行的无人机与材料消费。各次清场都在全部子机返回之后进行。原生煤灰、原生炸药层、上轮未消失的炸药、材料不足或动作失败都会输出位置或原因。派发、布药和等待共用每田15游戏秒截止时间；异常时回收句柄并报告，不把未完成爆破记成成功。

## 采矿大师的窗口

成就目标是60游戏秒内获得1,000,000 Block，平均约16,666.67/游戏秒。主机在每次点火前后记录实际时间和Block库存，删去超过60秒的起点，只报告剩余起点至当前的净增长。这是一个不超过60秒的保守窗口，不按单次爆炸收益推算整分钟。

`block_blast` 输出田号、爆破轮次、本田净增、窗口实际秒数和窗口净增。只有窗口实际净增达到1M时，才输出“采矿大师数量条件已达到”；该输出不读取Steam成就状态。窗口跨换田保留，包含首次派机、布药、等待和重生耗时。

## 静态依据与验证范围

机制依据为游戏源码的 `Dynamite.OnDig/GetExplosionEnergy/Explode`、`DynamiteHat.OnDig`、`Drone.Dig` 和 `SweeperController.ClearAndScorePuzzle`，资源依据为[地下资源](../simulator/local_simulator/underground_resources.json)与[基础资源](../simulator/local_simulator/resources.json)的炸药、向日葵、可种地面和科技上限。爆炸能量、收集掉落、原生炸药奖励及种子成本均按这些入口核对。

历史单钻稀疏孔的三seed平均约502.90 Block/游戏秒，来源见[地下功能效率记录](underground-functional-validation.md)。该数字属于旧算法，不能当作连锁版的结果。连锁版只完成游戏语法静态编译、LSP和代码自审；本地吞吐、真实60秒窗口、连锁覆盖率、当前游戏精度与实际成就解锁均未验证。没有效率对照报告，不覆盖真实存档。
