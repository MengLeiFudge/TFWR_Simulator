# lb_pumpkins_single

## 榜单目标

- 目标资源：`Items.Pumpkin`
- 单机路线
- 当前脚本默认目标数量为 `10000000`

## 收益机制说明

- 南瓜和胡萝卜一样生长在耕地上，而且种植南瓜会消耗胡萝卜。
- 当一个方形区域内所有南瓜都完全成熟时，它们会合并成一个巨型南瓜。
- 这里最关键的阻塞是 `Dead_Pumpkin`：
  - 南瓜完全成熟后有 `20%` 概率枯死
  - 枯死南瓜不会掉落任何东西
  - 枯死南瓜不会参与合并
  - 枯死南瓜还会阻止周围南瓜合并
  - 但在它上面直接种新南瓜会自动移除它，所以不必先 `harvest()`
- 南瓜单块收益规则是：
  - `1x1 -> 1`
  - `2x2 -> 8`
  - `3x3 -> 27`
  - `4x4 -> 64`
  - `5x5 -> 125`
  - `n>=6` 时变成 `n*n*6`
- 这直接推出：
  - 单块最优尺寸就是 `6x6`
  - 因为从 `6x6` 开始，单位面积收益不再继续上升
- 所以单榜南瓜的正确理解非常固定：
  - 直接设世界大小为 `6`
  - 然后围绕一块 `6x6` 做种收循环

## 通用注意事项下的榜单特化

- 南瓜单榜的核心不是 companion，而是整块连通与整波成熟
- 主瓶颈通常在：
  - dead pumpkin 补种
  - 尾部未熟格
  - 最终 harvest 顺序
- 因此应优先减少“整波成熟被打断”的次数
- 但在当前规则下，“块大小是否还要猜”这个问题已经基本结束了：
  - `6x6` 就是单块最优尺寸
  - 这榜真正要优化的是 `6x6` 里的执行节奏，而不是再去试 `4x4` / `5x5`

## 候选策略方向（猜测 / 待验证）

### 方向 1：保留 `6x6`，优先处理 `Dead_Pumpkin` 最易出现的坏点

- 核心思路：块尺寸不变，专门优化哪些格子最容易拖成 `Dead_Pumpkin` 阻塞点
- 主瓶颈：只要有一个死点没补上，整块就不能合并
- 可能更强的原因：对单机南瓜来说，修补坏点的优先级比别的局部操作都高
- 优先探针：
  - 哪些位置最常成为最后的死点
  - 提前补这些点后整轮耗时是否下降

### 方向 2：保留 6x6，但把尾部未熟格单独做 last-mile 策略

- 核心思路：大部分格子按原波次推进，最后 1 到 3 个未熟格进入专门处理流程
- 主瓶颈：最后几个格子拖整轮
- 可能更强的原因：尾部专门化后，不必全图陪最后几格等待
- 优先探针：
  - 每轮最后未熟格数量分布
  - last-mile 流程对单轮耗时的影响

### 方向 3：把肥料严格限定到“最后一个坏点”

- 核心思路：不在中段滥用肥料，只在确定它能结束整轮时使用
- 主瓶颈：肥料如果用早了，可能只是加快中间格，却没解决真正拖尾格
- 可能更强的原因：把肥料集中在最后坏点，能最大化整波收益
- 优先探针：
  - 肥料使用位置与整轮结束时间的相关性
  - “最后一格专用肥料”是否优于当前分散补救
