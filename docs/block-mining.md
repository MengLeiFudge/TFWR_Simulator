# 建材深钻与矿物勘探

普通功能入口[block.py](../scripts/functional/block.py)使用全科技、32×32农场、一台无人机和唯一爆破钻；`block(target=-1)`无参持续生产，非负参数为最终库存下限。普通全科技采矿与排行榜的初始库存、科技、地形限制分别核算。

## 开采路径

同一根孔连续向下开挖，利用已打开深孔进入新地层，不反复回到浅层。首次清场后，整次执行仍有Jump额度时调用`production.jump_once(Unlocks.Dynamite)`。每次爆破消耗一份Dynamite，`Dynamite.Explode(..., collectDrops: true)`按实际清除地块入库；原生雷块和煤灰可以补充传播能量。塌方清除的块不会自动变成收益。

当前入口每次挖掘前检查炸药，缺料或`dig()`失败返回原因；每16次采样目标、硬度与窗口。原版在炸药0时可能仍允许普通手挖，不能将这种成功返回当持续爆破。`resources.materials`按`DYNAMITE_RESERVE=2000`预备一次材料储备，不限制持续入口总次数；原生扫雷层也可能发放炸药，净消耗按库存实测。

煤、铁、石英和石化南瓜共用`mining.mine`的连续深钻，各自保留目标参数；当前速率与旧勘探路线取舍见[普通地形深钻](script-rate-validation.md#普通地形深钻与勘探)。独立功能效率不补算其他材料生产时间，动作仍实扣材料；排行榜筹资与每次查询必须全额支付。

## 采矿大师的窗口

成就要求60游戏秒获得100万Block，平均16666.67／秒。原版`Simulation.RecordCollectedItem`传`CurrentTime`给`Achievements.CollectItem`，后者按60秒Duration维护滑动窗口；这是游戏时间。入口从初始化前库存计时，包含清场、改尺寸、首次Jump和挖掘。

每16次挖掘记录游戏时间和实际Block库存，淘汰超过60秒的起点，历史按下标和分段压缩维护；只有实际净增≥100万才报告数量条件达成，不读取Steam账号状态。成就验证可传新增100万的库存目标，常规持续调用不加五分钟退出条件。

## C#充足炸药复核

较早C#复核中，初始炸药0的首10秒仅增7764；材料充足的0～10秒与10～20秒分别增145587、137057，乘6都低于后续真实60秒的1476502。后者使用尚未加缺料检查的版本，消耗1697炸药、墙钟3.779秒，实际窗口48.69秒增1044581。

深层爆炸和正常扫雷结算造成跳跃入库，首段线性外推不能单独判定效率或成就失败。此前初始炸药0、300秒仅增318443的报告不能代表持续爆破；全科技不等于材料已备足。报告预算到时按实际推进和净增长计算，未结算批次另记。

## 铁与石英勘探

- `prospect_iron()`付1 Coal，返回最近铁矿的水平引导方向或`None`。方向按非环绕坐标给出，选目标还考虑未挖覆土深度；`None`既可能已对齐目标柱，也可能范围无矿，须实际挖掘确认。
- `prospect_quartz()`付1 Iron，返回当前位置至最近石英的三维直线距离或`None`，原版搜索范围32格。例如10只表示距离10格，不直接给x／y／z或水平方向。
- 开挖改变当前位置高度、地形及最近矿。比较多点距离必须用各点实际高度，在全部锚点准备后重读；最近距离可能属于不同矿，三点几何只能选下一钻孔，实际开采与有界回退仍必需。

依据为原版`Drone.ProspectIron`、`Drone.ProspectQuartz`及`FindClosestOre*`；当前C#原生实现见[World.cs](../simulator/headless/Native/World.cs)。旧Python接口名仅属历史资料，不作为当前调用入口。

早期普通田煤方向追铁的60秒三seed均值498.0529→669.4077 Iron／秒，提高34.4049%，有限5000目标9.389848秒实际5104并回收；后由连续爆破替代。石英的单机贪心、三点定位和主机准备后32机分区等七个代表均慢于当时237.4331／秒稀疏爆破，原因包括多次开孔、距离变化、深孔陷阱和最慢工人回收。113.929873秒预算样本按实际时长计算，不补成120秒。

这些结果只约束所测实现。排行榜可能没有勘探材料或禁止Jump／爆破，不能套普通田充足库存；反之也不能因榜内筹资太贵否定功能勘探。各榜当前选择见[多机矿物](leaderboards/lb_ores.md)、[单机矿物](leaderboards/lb_ores_single.md)及[地下Reset](leaderboards/lb_fastest_underground_reset.md)。
