# f0：多机分区煤矿开采

在游戏中停止原程序，再运行已有的 `f0.py`。脚本按 `max_drones()` 和地图面积划分区域，开局派出多机，各机负责一个互不重叠的矩形。32×32 地图、32 台无人机时，每台负责 32 个平面格子对应的地下列。

各机先巡视本区，汇总全图现有最高地面。随后按公共目标 z 逐层开采，每台以蛇形路线检查本区全部位置。逐层检查会挖开本层普通岩石，露出下一层，因此找矿覆盖整张地图。已有深坑中低于目标层的位置直接跳过。

发现煤炭时，先记录煤块所在层，挖掉它，再把本区内同层八邻格加入待查列表，优先追踪煤脉分支。每项保存 `(x, y, z)`，同一位置、同一层只加入一次；列表清空后继续巡视本区其他位置，也会检查与当前煤脉不相连的小煤片。覆盖层中遇到的其他煤炭也扩展分支。

各机只挖自己区域内的列。跨边界的煤由相邻区域的无人机巡视发现。`spawn_drone()` 会复制参数，因此任务间通过不相交区域分工，任务完成后用 `wait_for()` 汇总结果。所有区域完成当前层后，才降低公共目标 z 并开始下一轮。

主机同样参与开采。无人机生成失败时，主机补完对应区域。移动失败、遇到不可破坏的方块或挖掘后地面没有下降时，该任务报告失败；主机等待已启动任务结束后退出。实际塌方仍受游戏地形规则影响，脚本不能恢复此前已塌掉的煤块。

入口 `f0()` 负责分区和逐层协调；`divide_regions()` 划分区域，`run_jobs()` 分派并回收任务，`mine_region()` 巡视区域，`mine_coal()` 处理八邻接煤脉。运行需要已解锁采矿、煤炭、多机，以及函数、列表、集合、元组和导入等所用语法。

实现依据本机游戏的多机 API、`CoalFeature.Generate`、`Execution.ApplySideEffect` 的 `GetGroundType` / `GetPosZ` / `Dig` 及塌方规则。验收以静态审查、Python 语法和本机游戏 API 的 LSP 为准；实际多机采矿运行尚未验证，本地模拟器尚未覆盖地下机制。
