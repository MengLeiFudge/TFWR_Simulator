# 策略研究优先级

研究基准：2026-10-24刷新的[排行榜缓存](leaderboard_targets.md)。按本地复跑参考与#10时间的比值选择研究对象，#1只作参考。历史本地成绩未全榜重测；新候选先做机制预算和本地模拟，再以真实游戏完成轮确认。协作阶段的方案、分工与推进状态以“TFWR 排行榜策略优化”房间合同为准。

## Fastest Reset：提前伴生升级的回本

当前`step4()`已解锁Dinosaurs 1，但`step5()`仍先刷金币，再升级恐龙和生产最终骨头。历史step4约2700秒，已经超过#10整轮1966.927秒；即使末尾骨头阶段免费也达不到目标。因此首项研究是解锁路径的结构预算，不能只抠最终换帽开销。

候选在step4后、金币大生产前，先生产刚好足够的骨头购买Polyculture 2。先核对当前成本和前置条件；历史成本记录为10000 Bone。保留Mazes 3、Megafarm 3及最终Leaderboard成功条件，比较：

`提前骨头与补给时间 + 升级额外时间 < 原Weird生产时间 × (1 − 1/有效吞吐倍率)`

有效倍率来自真实伴生命中和生产周期，不直接把科技翻倍当作整条产线翻倍。需要记录阶段开始/结束的时间、库存和科技；预算必须计入仙人掌准备、恐龙动作、切帽清场及恢复产线成本。

执行先用`preset=reset`和seed 1校准当前脚本阶段，单次本地运行不超过60秒墙钟，并设置API/语句上限。若完整流程过大，先缩到相关阶段；模型缺口应报告首处分歧，不能把缺口当成策略失败。预算成立才扩到至少3个seed，稳定改善后进入有界实机验证。这只是通向#10的一项结构假设，不承诺单次改动填平80.6%的差距。

已有Watering/Fertilizer上限、Power阈值、跳过Polyculture 1、金币大批量等失败记录仍有效，不重新做同类枚举。后续按实际阶段占比决定是否继续解锁路径或切换榜单。

## Sunflowers Single：整批收完再重种

当前机制中每株基础Power为1；被收株是全场最大花瓣且场上至少10株时获得8倍。花瓣数不直接乘产量。当前实机机制对照见[作物机制](../../mechanism_model/local_simulator/mechanisms.md)，与早期文档及部分离线代理采用的“错收惩罚链”不同。旧实测慢成绩仍保留，但不能从使用旧机制的代理直接推导所有新结构都失败。

#10为253.958秒，10000 Power要求净吞吐至少39.38/s。即使每次都获得8 Power，也至少需要1250次有效收获，实际还须补偿Power消耗。按该榜真实科技换算一次200t操作的时间，再计算每次收获可分配的移动、种植、收割与补水预算；初始化和成熟等待另计。

已完整复验的方案保留9株永久7瓣支撑，其余生产位按批种植、按花瓣从高到低收完，本批结束前不重种。这样收割期间不会出现新种高花瓣抬高最大值；最后一株生产作物收割前仍有9株支撑，满足10株门槛。支撑初始化的重抽与清除成本全部计入。

只比较6×6的27生产位和8×8的55生产位两种布局。同瓣内先采用环绕曼哈顿最近邻，不做路径全排列。所有生产位每批都收，不采用持续跳过低花瓣的max-k路线。成熟等待、9桶选择与移动成本都必须进入本地预测。先核对历史分桶实现是否已经测过同样的延迟重种结构；相同结构不重复验证。

与当前6×6盲收用相同初始库存、科技和seed作对照，至少3个seed；差异超过10%增加样本。稳定显著改善才进入实机，足够统计并在真源重新部署确认后才替换正式实现。新方案的假设是避免持续重种制造新最大值，不是等待稀疏15瓣。

## Maze：只压缩当前路线的局部捷径

当前源码`Treasure.CompleteRepositioning`在每次宝藏移动后，对每条内部相邻边以0.002概率拆墙；墙不会恢复。同一道原始墙经过100/200/300次移动后被拆的概率分别约18.14%/32.99%/45.15%。这只是边开放概率，不是可节省路程的比例。当前`solve_maze_in_area`仍走探图得到的静态中心路径，`new_paths`没有新增内容，因此不会利用后续拆墙。

32×32、Mazes 6时每次兑现32768 Gold，目标9863168共需301次兑现，即最多300次迁移加最后收割。Speed 5且有Power时一次200t动作约0.032922秒。#10整轮42.777秒相当于每次兑现平均4.32个串行动作预算；若假设探图/派发先占15秒，只剩2.80个。该预算衡量关键路径，不可直接套到所有无人机动作之和；15秒只是待实测更新的预算假设。

待筛选候选保持现有探图、radius=14、owner_wait=0.2、负责区和回中心结构，只压缩本次已缓存路线：

1. 将中心到目标的路径表示为不重复节点序列，沿途从当前节点查找几何相邻、但位于路线更后方的节点。只检查能跳过至少两条旧边的候选通道。
2. `can_move`确认通道已开才走，优先跳到最靠后的可达节点；不成立就走原下一步。路线索引严格递增，不进入旧路线外未知格，不做全图BFS、墙扫描或所有点对预计算。
3. 记录实际走过的方向，回程沿其反向返回原中心；已通过的捷径不会因墙恢复失效。维持现有宝藏变化、结束和回中心处理，不将私人字典误当无人机共享状态。
4. 缓存上限限定为当前已选路线及其局部候选边。几何索引、邻接判断、失败查询与回程记录都计入游戏操作成本，不把这些成本藏在离线模型中。

这与历史每步四向刷新整张图、路径松弛、当前位置BFS及漂移式不回中心不同；历史失败证据不能直接证明本候选有效或无效。首筛先在真实生成的少量迷宫及少量实际路线中估算“所有几何捷径都免费开放”能省的边数；若乐观上界都无法抵消实现开销则停止，不进行全图全组合搜索。上界成立后才由执行方编写一个候选，与当前脚本在相同场景、seed 0/1/123下比较完整时间、阶段时间、move/can_move/解释器tick和达标率。

候选暂不进入实机队列：先完成向日葵实机。Maze本地完整轨迹未校准时须先核对基线，不把超时/首差当算法失败。进入实机需全部样本达标、初始化不明显拖延、稳定节省的移动覆盖额外判断，并取得足够明显的整轮净收益。若仍远离#10，记录剩余预算，不用该小结构宣称已经找到前十路线。

## Carrots Single：按收获时刻保护伴生支撑

当前真实资源和源码表明：Carrot基础掉落1，满级Carrots 10提供512倍，Polyculture 5命中提供160倍，每次正常成熟伴生收获81920。目标一亿至少需1221次有效收获；#10为235.344秒，平均每次只允许0.192747秒，即5.855个200t动作，初始化、成熟等待和解释器开销尚未扣除。静态四锚点Bush支撑的单次命中率为21/24/3=29.167%，仅收割/重种及失败重抽已需平均6.857个200t动作，无法靠换支撑类型达到该预算。

`Growable.GetYield → YieldFactor → HasCompanion`在收获时读取支撑格的当前实体。当前`roll_adaptive_companion`只在重种后确认匹配，其他三个锚点随后可以通过`rewrite_adaptive_support`改写同一格；`process_anchor`成熟后直接收割，不再确认伴生。存在已接受伴生在生长期失效的路径，影响频率尚未测量，不先断言是主要瓶颈。

旧`.codex/tests/carrot_single_rewrite_cooldown_screen.py`在类型匹配或重写成功后立即增加`accepted`，没有保存待成熟作物，也没有在未来收割时重查支撑。其“冷却无收益”只能描述当时的重抽/重写成本代理，不能排除保护实际待收伴生。旧实机静态布局、双锚点、支撑类型和距离阈值的失败成绩仍保留。

执行顺序：

1. 先在当前榜单初始条件下运行原脚本seed 0/1/123：12种库存显式归零，仅Hay/Wood/Power各十亿，Expand 5、Megafarm 0、其余满级，Carrot目标一亿。每个seed有界运行，先检查完成率及成熟收获的倍率分布。利用报告`harvests`区分Carrot的81920、512和0收益，0收益重抽不算成熟失配；记录总move/harvest/plant/use_item及游戏时间。若出现其他正收益值，先查感染/版本和模型，不套二值分类。
2. 若成熟失配很少、恢复全部损失的乐观收益也不足以覆盖记录与额外拒绝成本，则停止该候选。新鲜实机基线在游戏队列空闲时补，旧517.719秒仅作参考。
3. 有明显失配才实现一个“直到收获才释放支撑”的候选。每个生产锚点记录已接受的支撑坐标和类型；同类型请求可共享，支撑记录引用计数。已被待收胡萝卜使用的支撑不得改成另一类型，冲突请求继续原有重抽；原锚点实际收割后先释放旧引用，再种植并申请新引用。仍保留四锚点、原访问顺序、d<=2改写和补水规则，不引入冷却时间参数或跨无人机共享假设。
4. 初始化先完成非锚点支撑，再处理四个生产锚点，避免后续初始化覆盖已申请的支撑；新增移动全部计费。候选保留API/步数/墙钟上限及阶段日志，遇到上限如实停止。统计初始化、成熟失配、冲突拒绝、重抽、支撑改写与完整时间，不能只汇报匹配成功次数。
5. 在相同场景和3个seed下对照原版；减少失配必须抵消新增重抽、成熟等待和记录开销，且全部达标。只有稳定净改善才进入短时实机，再完整打榜、迁真源复验并保存三类时间；失败保留同名记录，不继续枚举冷却和支撑过滤参数。

这是保证待收伴生兑现的候选，不承诺足以缩短达到#10所需的54.5%。若失配占比不够或保护成本过高，应转向减少往返或改变生产/支撑安排的结构预算，而非压缩廉价查询。

## 后续榜的已有约束

- Maze：历史探索约8～12秒，后续求解约80～90秒；只消除探索不足以达到42.777秒。下一候选须说明减少哪部分移动，避免重新做已失败的静态区域分派与锁。
- Carrots Single：四锚点、2×2 support、记忆命中和近距离重写已实现；距离阈值与选择性重写已有失败记录。先计算有效伴生周期。
- Dinosaur：历史`cycle_finish`约62.77%，`chase_fill`约22.03%。旧C#动作模型的苹果抽样不能代表当前Python模型；使用已实现x/y拒绝采样的脚本模拟器，并校准当前参数。
- Cactus：历史完整统计198轮均值36.493秒，当前#10已变为18.837秒。邻接逆序交换量是重要下界，不能用廉价measure优化解释48.4%的缺口。

## 模型与证据边界

[本地脚本模拟器](../../mechanism_model/local_simulator/README.md)已实现操作计时与离散事件，记录中的约900秒单seed场景最大时间差0.02605秒，详见[验收范围](../../mechanism_model/local_simulator/validation.md)。这不表示任意完整策略已对齐，尤其完整Fastest Reset尚未验证。

每个榜的实现、失败与接近候选、实机请求和统计写入同名`lb_xxx.md`。旧记录中“下一步”可能已被后续实验否定；先核对版本、机制和后续证据，再决定是否复用结论。模拟预测与轮内ETA始终不能代替真实成绩。
