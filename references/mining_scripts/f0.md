# f0：5×5 多机水稻循环

停止旧程序后，在游戏中运行已有的 `f0.py`。需要已解锁水稻，并有至少 25 台无人机容量。脚本设置 5×5 世界，调用一次 `jump(Unlocks.Rice)`，然后以 24 台子机加主机覆盖 25 个格子。

每轮分两个阶段：

1. 整地：挖掉地表、泥土和上一轮收完后的干梯田，直到露出 `Grounds.Clay`。遇到黏土下方的其他岩层时，标记该格已耗尽，保留其他还能种的格子。
2. 种收：在黏土上种 `Entities.Rice`，用 `can_harvest()` 等成熟，再调用 `harvest()`。已耗尽的格子跳过。

全部整地任务结束后才开始种植；全部种收任务结束后才开始下一轮挖掘。生长和收获期间没有无人机挖掘，避免塌方破坏邻格稻苗。每轮收完输出新增水稻和总库存。

当 25 格都找不到可用黏土时，主机在所有子机结束后调用 `clear()`，重置地形，再从地表挖到新的黏土。不会重复调用本次运行只能使用一次的 `jump()`。重置发生在上一批水稻全部收获后。

生成无人机、移动、种植、挖掘或收获失败时会输出原因；已启动的有限任务全部结束后，主机退出。等待成熟时如果稻苗消失，也会报出位置并退出。可用游戏的停止按钮结束循环。

入口 `f0()` 协调循环与重置；`run_grid()` 分派并回收每轮任务；`prepare_cell()` 找黏土，`grow_cell()` 种植、等待并收获。`set_world_size(5)` 在大小发生变化时会重置地形；`jump()` 和耗尽后的 `clear()` 也会重置地形，因此运行前应先完成当前想保留的农场操作。

实现依据用户提供的水稻说明、本机游戏 API 及当前 `ClayFeature`、`Rice`、`Jump`、`Clear` 源码。验证限于静态审查、Python 语法和本机 API 的 LSP；实际多机种稻尚未运行，本地模拟器尚未覆盖这些地下机制。
