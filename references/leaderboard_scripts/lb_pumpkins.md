# lb_pumpkins

## 榜单目标

- 目标资源：`Items.Pumpkin`
- 多无人机路线
- 当前脚本目标数量为 `200000000`

## 收益机制说明

- 南瓜和胡萝卜一样，必须种在耕过的地 / Soil 上，而且种植会消耗胡萝卜。
- 南瓜榜的关键机制不是 companion，而是“方形区域内全部南瓜同时完全成熟后，会合并成一个巨型南瓜”。
- 这里有两个必须写死的规则：
  - 只要方形区域里有一个南瓜没有成熟，就不会合并
  - 只要方形区域里有一个南瓜枯死变成 `Dead_Pumpkin`，也不会合并
- 多无人机南瓜可以用任意一组对角判断整块是否已合并成熟：
  - 选任意一个角作为角 1
  - 对角作为角 2
  - 当 `measure(角1) == measure(角2)` 时，可以视为这块已经形成同一个 giant pumpkin，可以收割
  - 这比全块逐格扫描 `can_harvest()` 更适合作为整块成熟判定
- 南瓜在完全成熟后有 `20%` 概率枯死：
  - 枯萎南瓜不会掉任何东西
  - 枯萎南瓜不会参与合并
  - 它还会阻止周围南瓜合并
  - 但在枯萎南瓜上直接种新作物会自动移除它，所以不需要先 `harvest()` 掉枯萎南瓜
- 南瓜产量规则是：
  - `1x1 -> 1*1*1 = 1`
  - `2x2 -> 2*2*2 = 8`
  - `3x3 -> 3*3*3 = 27`
  - `4x4 -> 4*4*4 = 64`
  - `5x5 -> 5*5*5 = 125`
  - `n>=6` 时变成 `n*n*6`
- 这条规则直接推出：
  - 单块南瓜的最佳尺寸就是 `6x6`
  - 因为 `6x6` 开始已经触发封顶倍数，继续增大单块并不会提高单位面积收益

## 当前已知解法

- 单块最优尺寸已经很明确：`6x6`
- 多无人机当前已知解法不是“全图切成一堆 6x6”，而是：
  - 两个 `8x8`
  - 两个 `6x6`
  - 每片 `2` 个无人机
- 你给出的当前参考视频是：
  - `https://www.bilibili.com/video/BV1phsUzXEH9`
- 这套布局看起来诡异，但你给出的当前理解是：
  - 不是 `8x8` 本身比 `6x6` 单块效率更高
  - 而是单纯用 `6x6` 方案时，地盘至少要到 `13x13`
  - 但 `8x8 + 6x6` 混排时，两个 `8x8` 各占一个角，中间只留一个单格连接
  - 单格不可能长成大南瓜，因此可以把无效连接空间压到最低
  - 这样整体只需要 `16x16` 的地盘
- 你当前的进一步猜测是：
  - 最优摆法可能是让 `8x8` 和 `6x6` 都尽量放在四个角
  - 这样可以尽量减少起步时间
- 这部分先作为当前已知解法记录，不在本轮继续发散成更多块尺寸猜测

## 通用注意事项下的榜单特化

- 南瓜榜的主收益不是 companion，而是 mega pumpkin 连通块
- 因此“整块同步成熟、整块一起结算”通常比单格局部最优更重要
- `pumpkin3` 结果修正了之前的判断：
  - 单块尺寸不应被简单钉死在 `6x6`
  - 大量低调度成本小块并行，比少数大块精修更适合真实游戏短窗成绩
  - 真实瓶颈不是“单块理论收益最高”，而是“多少无人机能持续低开销地产出和修补”
- 这个榜单要重点看：
  - `Dead_Pumpkin` 的补种优先级
  - 多块布局与起步时间
  - 多无人机各自负责独立小片区，避免集中抢同一大块的尾部修补

## 失败对照

- `main2` 并不是收益思路失败，而是当前实现形态在本地 sim 下会触发 `error_assign_type_mismatch`
- 这说明对南瓜榜来说，代码结构本身也会成为阻塞，而不仅仅是策略方向
- “把全图简单切成大量 `6x6` 小块”这条理解
  - 当前应视为过时口径
  - 因为已知实战解法已经不是这个方向
- 主机只测角、完全把补洞交给 helper
  - 2026-04-24 真实验证：45 秒窗口无完成轮次
  - 结论：单个 helper 全块扫描不足以独立完成修补，主机等待期间仍必须参与修补
- 2026-04-25 只让 helper 跳过翻地、补水仍用旧 1 桶
  - 真实 2 轮均值 `48:08.378`
  - 能消除 `Grassland` 种植警告，但相对 `48:01.249` 没有明显提速

## 候选策略方向（猜测 / 待验证）

### 方向 1：继续压缩 `pumpkin3` 小块并行

- 核心思路：保留当前已验证快路线，优化块型组合、块位置和日志/退出开销
- 主瓶颈：当前约 `6:41`，已经接近外部候选原始单轮；继续提升要从小块效率差异里找
- 可能更强的原因：真实成绩已经证明该方向远强于 `main4`
- 优先探针：
  - 分别禁用部分 `path_36` / `path_55` / `path_66` 片区，看总时长变化
  - 比较 `main1` 与 `main2` 的规则阵列成绩

### 方向 2：专门优化 dead pumpkin 修补

- 核心思路：保持每机独立片区，但降低 `unchecked` 修补队列的移动和重复补种成本
- 主瓶颈：`Dead_Pumpkin` 是合并的硬阻塞，只要修补慢一步，整片都会停
- 可能更强的原因：`pumpkin3` 已经靠并行吃到大收益，剩下尾部主要是补洞和成熟等待
- 优先探针：
  - 记录每轮 `unchecked` 最大长度
  - 比较肥料 last-one 加速阈值对单轮时间的影响

### 方向 3：把 `main4` 作为失败对照保留，不再主攻

- 核心思路：旧“两块 8x8 + 两块 6x6”路线仍可记录，但不再作为默认优化主线
- 主瓶颈：旧路线最大问题是大块尾部修补/等待调度成本过高
- 可能更强的原因：只有当新发现能显著降低大块尾部成本时，才值得回头
- 优先探针：
  - 不主动继续投入；除非外部新脚本证明大块路线可进 `10min` 内
